# Plan（先写方案再动手）

> 触发：多步骤任务（3+ 步）、大改动、用户说"搞个 X"。写方案 → 确认 → 执行。

## 什么时候必须写方案
- 要改多个文件/模块
- 有几种做法可选（取舍需要拍板）
- 涉及数据/配置/外部依赖
- 用户不在场时的大活（写完方案留档，等确认）

## 方案结构（精简版）
1. **目标**：一句话，做什么、不做什么
2. **现状**：相关代码/配置在哪（文件路径）
3. **方案**：步骤列表，每步做什么、改哪个文件
4. **风险**：可能踩的坑、回滚方式
5. **验证**：怎么知道做完了（命令/测试）

## 平衡原则
- 方案要短：能 20 行说完不写 200 行
- 大活才写方案，小活直接干（别为每个改动写论文）
- 写方案的时间 = 省的返工时间的零头

## 与用户确认
- 有取舍 → 给选项 + 推荐，别只给一个
- 用户拍板后 → 按方案执行，中途大改先回来说
