# Code Review（代码审查）

> 触发：提交前审查、PR 审查、重构前检查。目的：抓真问题，别鸡蛋里挑骨头。

## 审查顺序（按重要性）

1. **正确性**：逻辑对吗？边界情况？错误处理？
   - 空输入/空列表/None、越界、并发、超时
2. **安全**：密钥泄漏？路径注入？权限？
3. **可维护性**：三个月后的人（包括自己）能看懂吗？
   - 命名、函数长度、魔法数字、重复代码
4. **性能**：明显 O(n²)？循环里做 IO？N+1 查询？
5. **测试**：新代码有测试吗？测试真的会失败吗（不是永远绿）？

## 输出格式
- 按严重度分级：🔴 必须改（bug/安全）→ 🟡 建议改（维护性）→ 🟢 可选（风格）
- 每条给出：位置 + 问题 + 具体改法建议
- 别只报"这里不对"，给出修法

## 自己的代码也要审
- 提交前自审：diff 从头读一遍，当别人写的看
- 检查：调试代码有没有删（print/日志前缀）、TODO 有没有留

## 红线
- 不改秘密进仓库（.env、key、token）
- 不盲目信任自己刚写的代码——手滑和脑滑都是常态
