# Test-Driven Development（TDD）

> 触发：新功能/修 bug/重构。红-绿-重构，一步都不跳。

## 循环（每次只走一小步）

```
RED（写失败测试）→ GREEN（最小实现让它过）→ REFACTOR（清理，保持绿）
```

## 步骤

1. **先写测试**：描述"希望的行为"，不是"现在的行为"
   - 命名：test_要测的行为
   - 一个测试只断言一件事
2. **看它失败（RED）**：确认失败原因是对的（缺实现，不是测试写错）
3. **最小实现（GREEN）**：只写让测试过的代码，不写多余的东西
4. **重构（REFACTOR）**：去掉重复、改名、理结构——每步都重跑测试
5. 重复，直到功能完整

## 测试质量
- 快（毫秒级）、独立（可乱序跑）、确定性
- 测行为不测实现细节（别断言内部函数调用）
- 一个失败信息要能告诉你哪坏了

## 什么时候可以放宽
- 一次性脚本/探索性代码 → 可跳过，但跑完要清理
- 集成/端到端 → 保留关键路径的冒烟测试

## 与调试配合
修 bug：先写复现测试（RED）→ 系统化调试找根因 → 修到绿 → 测试留下来防复发。
