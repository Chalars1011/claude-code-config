# Simplify Code（简化代码）

> 触发：代码变复杂了、刚写完一大坨、重构前的清理。**删比写重要。**

## 思路
- 代码变复杂是因为：历史包袱、过度设计、复制粘贴
- 简化目标：让下一个读代码的人（三个月后的自己）少花一半时间

## 检查清单
1. **删死代码**：没被引用的函数/变量/import/注释掉的代码 → 删
2. **删重复**：同样逻辑出现 2+ 次 → 抽函数（但别抽过头，抽象层级别超过两层）
3. **缩短链条**：a.b().c().d() 超过三层 → 拆开命名
4. **砍参数**：函数参数超过 4 个 → 想想是不是职责太多
5. **拆大函数**：超过 50 行且做多件事 → 拆小
6. **改坏名字**：名字骗人（get 不返回、is 不是布尔）→ 改名

## 平衡（别把代码改坏）
- 每次只做一个简化动作，改完跑测试
- 不简化：性能热点、与外部格式强耦合的地方
- 简化不是炫技：别人能看懂 > 自己觉得优雅
- 别在任务中途顺手大重构（夹带私货是 bug 之源）

## 验证
- 改完：测试全绿 + diff 只减不增（行数变少是常态）
- 行为不变，结构变好——功能改了就不算简化
