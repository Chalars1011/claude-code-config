# 记忆核心设计原则（D:/Aurelia 五层模型）

> 2026-08-08 设计，有学术依据（见 docs/记忆架构.md）。通用原则，任何 agent 记忆系统可复用。

## 五层 + 处理方式
| 层 | 内容 | 处理 |
|---|---|---|
| 人格 | soul.md | 常驻注入（几乎不变） |
| 事实 | facts.md | 常驻注入（精简版，慢变） |
| 经验 | lessons.md | 常驻 + 出错必写 |
| 任务 | tasks.md | 常驻 + 双向同步 |
| 流水 | journal/ conversations/ | 不注入，按需检索 |

## 三条铁律（学术依据）
1. **注入 = 工作集，必须短、关键信息靠前**（Lost in the Middle：U 型曲线，中间信息最废；上下文越长中间越废）
2. **档案 = 磁盘，无限大，按需取**（MemGPT 分页思想：窗口是主存，档案是磁盘）
3. **规矩 = 少而硬，宁缺毋滥**（IFScale：指令越多遵循率越低，最强模型 500 条指令只有 68%）

## 机制
- 读心：开口前按需读（事实类才读，闲聊凭心答，禁止扫街）
- 写心：说完写 journal/当天 + 重要对话 conversations/ + 纠正 lessons + 任务 tasks
- 回流：Hermes 记忆 → 档案（每日 4 点 cron）
- 归档：会话 → conversations/（on_session_end hook）
- 三层保险：自觉写 → hook 强制 → cron 兜底
- 承诺必写：查尔斯说"记住"→ 当场写，写完再答
- 事件是铃铛（可丢无损），真相在档案（可靠永久）——两者分离
