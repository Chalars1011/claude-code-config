# AI 团队搭建流程（多角色 Sub-Agent）

> 创建: 2026-08-10 | 更新: 2026-08-10 | 适用: Claude Code 团队模式 | 类型: 搭建流程
> 来源: 2026-07-25 团队成立 + 2026-08-06 伊莉丝入队 + 2026-08-10 复盘

## 适用场景
给 Claude Code 搭多角色团队（主控 + 研究员 + 执行者 + 审查员 + 美术师）。

## 团队结构（咱们的配置）
| 角色 | 文件 | 职责 | 必调场景 |
|------|------|------|----------|
| 主控（奥蕾莉亚） | CLAUDE.md | 协调决策 | 全局 |
| 研究员（莉丝） | agents/lys.md | 搜+读+方案对比 | Think First 流程 |
| 执行者（锐亚） | agents/rhea.md | 写代码+验证 | Execute 阶段 |
| 审查员（艾达） | agents/ada.md | 对照规则审计 | 代码改动完成/会话结束前 |
| 美术师（伊莉丝） | agents/art.md | 义眼看图+画笔出图 | 美术相关必调（HARD RULE） |

## 搭建步骤

### 1. 定义角色分工
- 先想清楚团队要解什么问题，再定角色（咱们是"游戏开发流水线"需求）
- 每个角色一个 `~/.claude/agents/<name>.md`，frontmatter 写 name/description/tools/model

### 2. 写角色卡（agents/*.md）
- description 要写清"什么场景必调这个角色"（否则主控不会主动调）
- tools 限定（如美术师只给 Read/Bash/Write/Edit/Glob）
- 正文写：核心工具（含命令）、核心职责、硬规则
- 角色卡要含"项目专属知识"（如 art.md 里的 card_roles.json 映射表）

### 3. 立调用规则（CLAUDE.md）
- 明确"什么阶段必调谁"：Think First → 莉丝；Execute → 锐亚；改完 → 艾达；美术 → 伊莉丝
- 关键场景设 HARD RULE（如"美术必走伊莉丝，义眼不过关不发布"）
- 规则要短而硬（IFScale：指令越多遵循率越低）

### 4. 配模型
- 全队统一模型（咱们是 DeepSeek V4 Flash），settings.json 与子 agent 配置同步
- 注意：换模型要同步所有角色卡 + settings.json，别只改一个

### 5. 验证
- 每个角色单独测一次：调它干它的本职活，确认工具能调通
- 测 HARD RULE：主控想绕过美术自己改图，应该被拦

## 关键坑（血泪）
1. **角色卡 description 写不清楚** → 主控不知道何时调，角色闲置
2. **工具没限好** → 美术师用像素统计冒充美术判断（08-06 查尔斯拍板禁止）
3. **规则太多太软** → 全是"建议"等于没有，要少而硬
4. **模型不同步** → 主控换了模型子 agent 还是旧的，行为不一致
5. **省钱铁律被推翻** → 规则是活的，查尔斯拍板变了就改（08-10 Pillow 禁用的例子）

## 验收标准
- 查尔斯说"美术相关" → 自动走伊莉丝
- 改代码 → 艾达审过才交付
- 调研 → 莉丝出方案对比
