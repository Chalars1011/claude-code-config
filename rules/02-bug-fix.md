# Bug 修复流程

## 触发条件
用户报告 bug 时执行。不是"你说什么我修什么"——要先定位根因。

## 流程（每步必须打标记）

### Step 1: 定位根因
- 读相关代码, 不要猜
- 有旧版本? 对比旧代码和新代码的差异
- 复现条件是什么？
✅ Step 1/4: [根因分析]

### Step 2: 搜索
- playbook/index.md → 同类坑？
- playbook 命中 → 读详细方案
- 如果 playbook 没命中 + 这是第 3+ 次修同类问题 → 必须搜索 web + context7
✅ Step 2/4: [搜索了什么, 结果]

### Step 3: 修复 + 验证
- 修复当前场景
- 验证
✅ Step 3/4: [改了哪个文件, 验证通过?]

### Step 4: 同步 + 沉淀
- 共享组件 → 必须提示批量同步 17 场景
- 第 3+ 次修同类问题? → 触发 P4: "值得写入 playbook?"
✅ Step 4/4: [同步了吗, 沉淀了吗]
